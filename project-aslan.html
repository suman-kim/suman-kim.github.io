01

배경 / 문제 정의

CCTV와 NVR은 제조사·모델마다 프로토콜과 전용 뷰어가 제각각이라, 현장에서는 장비마다 다른 툴로 실시간 영상·녹화·이벤트를 따로 확인해야 했습니다. 사이트와 채널이 늘어날수록 관제 부담이 빠르게 커졌습니다.

여러 사이트의 다채널 영상을 한 화면에서 실시간으로 보고, 녹화를 시간대별로 조회하고, 이벤트를 즉시 파악할 수 있는 통합 웹 관제가 필요했습니다.

04

핵심 문제 해결

smart_display

브라우저에서의 다채널 실시간 재생

CCTV는 대부분 RTSP로 스트리밍하는데, 브라우저는 이를 직접 재생하지 못합니다. 다채널 영상을 웹에서 부드럽게 보여주는 것이 핵심 과제였습니다.

해결
  • RTSP 스트림을 브라우저가 재생할 수 있는 HLS/WebRTC로 변환해 웹에서 재생
  • 채널별 스트림을 필요할 때만 열고 닫도록 관리해 불필요한 부하를 줄임

브라우저 제약을 우회해 여러 채널을 한 화면에서 실시간으로 볼 수 있게 했습니다.

hub

제각각인 장비 규격의 추상화

제조사·모델마다 프로토콜과 기능이 달라, 상위 관제 로직이 장비 종류에 휘둘리면 유지보수가 빠르게 어려워집니다.

해결
  • 장비 연동 계층을 어댑터로 분리해, 상위 로직은 통일된 인터페이스로 카메라·NVR을 다루도록 설계
  • 새로운 장비가 추가돼도 어댑터만 확장하면 되는 구조

관제 로직과 장비 연동을 분리해 장비가 늘어도 흔들리지 않는 구조를 지향했습니다.

bolt

이벤트를 늦지 않게 — 실시간 전달

관제에서는 이벤트를 '늦지 않게' 보는 것이 중요합니다. 폴링만으로는 지연과 부하가 함께 커집니다.

해결
  • 장비 이벤트를 WebSocket으로 관제 화면에 실시간 push
  • Redis로 채널·장비의 실시간 상태를 관리해 대시보드가 항상 최신 상태를 반영

수신과 상태 관리를 실시간 경로로 묶어 즉시성 있는 관제를 만들었습니다.
