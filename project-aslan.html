01

배경 / 문제 정의

CCTV와 NVR은 제조사·모델마다 프로토콜과 전용 뷰어가 제각각이라, 현장에서는 장비마다 다른 툴로 영상·녹화·이벤트를 따로 확인해야 했습니다. 사이트와 채널이 늘어날수록 관제 부담이 빠르게 커졌습니다.

여러 사이트의 다채널 영상을 한 화면에서 보고, 녹화를 시간대별로 조회하고, 이벤트를 즉시 파악할 수 있는 통합 웹 관제가 필요했습니다.

핵심 문제 해결

cast

영상은 네이티브 SDK로, 관제는 웹으로 — 역할 분리

브라우저로 다채널 CCTV를 저지연으로 디코딩·재생하는 건 한계가 큽니다(코덱·하드웨어 디코딩·다채널 부하). 영상 재생과 웹 관제를 한 덩어리로 묶으면 양쪽 다 무거워집니다.

해결
  • 영상 재생은 C++ 네이티브 영상 SDK가 담당 — 프론트에서 SDK를 호출하면 SDK가 장비에 직접 붙어 디코딩·렌더링
  • 웹(아슬란)은 무거운 영상 파이프라인을 지지 않고 장비·녹화·이벤트 관리와 관제 UI에 집중
  • 프론트(Next.js)가 한 화면에서 SDK 영상 영역과 웹 관제 UI를 함께 배치·제어

무거운 실시간 영상은 네이티브에, 관리·관제 로직은 웹에 두는 역할 분리로 양쪽의 강점을 살렸습니다.

bolt

이벤트를 늦지 않게 — 실시간 전달

관제에서는 장비·서버 이벤트를 '늦지 않게' 보는 것이 중요합니다. 폴링만으로는 지연과 부하가 함께 커집니다.

해결
  • 이벤트를 WebSocket으로 관제 화면에 실시간 push
  • Redis로 채널·장비의 실시간 상태를 관리해 대시보드가 항상 최신 상태를 반영
  • PostgreSQL에는 이벤트·녹화·장비 메타데이터를 적재해 이력 조회에 사용

실시간 경로와 이력 저장을 분리해 즉시성과 정확성을 함께 잡았습니다.
