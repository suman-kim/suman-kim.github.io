01 · Background

배경 / 문제 정의

문제

기존 카드·키패드 방식의 출입통제는 카드 대여나 대리출입 같은 인증 도용 문제에서 자유롭지 않았습니다. ONEPASS PRO는 얼굴 인식으로 이 문제를 해결하기 위해 시작된 프로젝트입니다.

요구사항

B2B 판매 구조인 만큼 각 사업장에 개별적으로 패키지를 설치하면서도, 운영사 입장에서는 여러 사업장의 서버 상태를 중앙에서 파악할 수 있어야 하는 요구사항이 있었습니다.

04 · Problem solving

핵심 문제 해결

PROBLEM 01

근태 관리손 대지 않는 자동 출퇴근 판정

얼굴 인식이 성공하면 단말기 화면에 출근/퇴근 버튼이 떠서 사용자가 직접 선택할 수 있었지만, 버튼을 누르려면 결국 손을 써야 했습니다. "얼굴만 대면 끝"이라는 얼굴 인식의 장점이 사라지는 지점이라고 판단해, 출근·퇴근 구분을 최대한 서버 내부 로직으로 자동 판정하는 방향으로 살리고 싶었습니다.

그런데 사용자마다 근태 규칙이 다르고, 규칙 안에는 근무시작/종료시간과 함께 "당일 퇴근" 타입과 "익일 퇴근" 타입이 구분되어 있습니다. 문제는 요일·날짜별로 전날이 휴무일 수도 있다는 점 — 단순히 "전날 = 어제"로 고정할 수 없는 구조였습니다.

해결 로직

  1. 단말기에서 이벤트 수신 시, 이벤트 발생일 기준으로 해당 사용자의 근태 규칙이 "익일 퇴근 타입"인지 확인
  2. 익일 퇴근 타입이면, 전날 근태 기록에 퇴근시간이 이미 있는지 조회
  3. 전날 기록에 퇴근시간이 없다면, 이번 이벤트를 전날의 퇴근시간으로 귀속 처리
즉 이벤트 시각이 아니라 근태 규칙 + 직전 기록 유무를 함께 판단해, 사용자가 버튼을 누르지 않아도 어느 날짜의 출근·퇴근인지 서버가 결정하는 구조입니다.

PROBLEM 02

이벤트 수신 안정성누락 이벤트 자동 복구

얼굴 인식 단말기의 인식 이벤트는 MQTT와 Socket.IO 두 경로로 서버에 전달됩니다. 실시간성은 좋지만, 네트워크 상황에 따라 가끔 이벤트가 누락되는 증상이 있었습니다. 근태·출입 기록의 정확성과 직결되는 문제라 그냥 둘 수 없었습니다.

해결

  • 단말기 자체에 저장된 이벤트 로그와 서버 DB에 적재된 이벤트를 백그라운드에서 주기적으로 대조
  • 서버에 반영되지 않은(누락된) 이벤트를 찾아내 자동으로 재등록
  • 실시간 수신(MQTT·Socket.IO)은 그대로 두고, 대조·복구는 별도 백그라운드 작업으로 분리해 안정성을 보강
실시간 경로로 놓친 이벤트도 결국 기록에 반영되도록, 실시간 수신과 정합성 보정을 이중화한 구조입니다.

PROBLEM 03

서버 운영비개발자를 위한 데스크톱 서버 매니저

Windows 기반 설치형 서버를 업장의 직원·관리자가 직접 실행해야 하는데, 이들을 터미널이나 CLI만 있는 환경에서 서버를 다루게 만들고 싶지 않았습니다. 비개발자도 화면을 보고 클릭 몇 번으로 서버를 켜고 끌 수 있어야 했습니다.

해결

  • Node · Electron 데스크톱 앱으로 "서버 매니저" 실행 프로그램을 제작
  • 서버 시작·중단과 실행 여부·헬스 등 상태 확인을 GUI에서 처리
  • 서버 데이터 백업 및 복원을 앱 내에서 바로 수행
  • 서버 포트 변경 등 실행 환경 설정도 앱에서 직접 조정
  • 서버 로그 확인으로 동작 상태와 오류를 앱에서 바로 열람
운영 주체가 개발자가 아니어도 서버를 안정적으로 켜고 끄고 관리할 수 있도록, 운영 인터페이스 자체를 하나의 데스크톱 앱으로 제품화했습니다.
